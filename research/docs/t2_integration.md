# T2 repository context and benchmark validation

Owner: Nirajan Bhandari. Implementation source: `teammate_2`.

## Delivered scope

This contribution contains snapshot verification, task cards, evaluator annotations,
source-provenance validation, benchmark-input isolation, worktree reproduction,
benchmark tests and T2 documentation. The existing retrieval, index, chunker,
agent controller, repository tools, orchestration, token accounting and analysis
implementations are unchanged. The root README and handoff are unchanged.

The original A/B pilot prompts, independent annotations and frozen experiment
configuration are preserved. The named `t2_context_v1` set contains eight task
records, 34 task-file judgments across 20 distinct paths, and 49 source spans.
Source/schema validation is complete. Student and independent peer relevance
sign-off is pending. These are separate statuses.

## Files and interfaces

| Artifact | Function |
| --- | --- |
| `benchmark/manifests/snapshots.json` | Complete original target/parent identities; Candidate E resolved |
| `benchmark/task_sets/t2_context_v1.json` | Eight neutral requests using the central four-field task contract |
| `benchmark/ground_truth/t2_context_v1/` | Evaluator-only relevance labels, symbols, spans, source hashes and test metadata |
| `benchmark/reviews/t2_context_v1/` | Decision inputs, ID mapping, upstream checks, overlap, qrels, review log and validation record |
| `benchmark_integrity.py` | Offline annotation and source-evidence checks |
| `benchmark_loader.py` | Exact method-input allowlist and explicit evaluator annotation-set selection |
| `snapshot_verify.py`, `snapshot_paths.py` | Commit checks and portable detached-worktree verification |

Method tasks contain exactly `task_id`, `task_prompt`, `context_budget` and
`agent_call_limit`. `method_input_bundle()` returns exactly `{"task": task}`.
Target metadata, judgments, spans and answer-bearing review files stay evaluator-side.
The marker checks validate structure and known leakage patterns; human task review
establishes semantic neutrality.

The evaluator selects the T2 annotations explicitly:

```python
from repo_search.benchmark_loader import load_ground_truth
annotation = load_ground_truth("pi_package_filtering", annotation_set="t2_context_v1")
```

The default remains the independent pilot annotation set. Qrels have three tab-
separated columns: `query-id`, `corpus-id`, `score`. The corpus ID is
`snapshot_sha:path`; grades are essential=2 and supporting=1. Unlisted files are
unjudged. No retrieval scores or experiment outcomes are generated by T2 tooling.

## Setup and commands

Run from `research/`. The original project README and handoff are at the repository
root. The package README supports the existing editable-install configuration.

```sh
python -m venv .venv
# Activate .venv for the operating system.
python -m pip install -e ".[dev]"
```

PowerShell, with paths set to the local Pi clone and detached-parent directory:

```powershell
$env:PI_REPO_PATH = "C:\Projects\pi-upstream"
$env:PI_WORKTREE_ROOT = "C:\Projects\pi-context-worktrees"
python scripts/verify_benchmark.py --repo-path "$env:PI_REPO_PATH" --dry-run
python scripts/prepare_worktrees.py --repo-path "$env:PI_REPO_PATH" --worktree-root "$env:PI_WORKTREE_ROOT"
python scripts/prepare_worktrees.py --repo-path "$env:PI_REPO_PATH" --worktree-root "$env:PI_WORKTREE_ROOT" --check-only
python scripts/validate_benchmark.py --repo-path "$env:PI_REPO_PATH"
python scripts/validate_benchmark.py --repo-path "$env:PI_REPO_PATH" --annotation-set independent
python scripts/build_t2_benchmark.py --repo-path "$env:PI_REPO_PATH" --check
python -m pytest tests/unit -q
```

Bash environment syntax is `export PI_REPO_PATH=/absolute/path/to/pi-upstream`
and `export PI_WORKTREE_ROOT=/absolute/path/to/pi-context-worktrees`.

The worktree helper prepares A/B by default. `--all` selects all eight parents;
repeated `--task-id` selects an explicit subset. It refuses existing dirty,
wrong-HEAD, attached or unrelated worktrees and preserves their contents.

The existing Stage 5/6 code reads `worktree_path` from the active snapshot manifest.
`prepare_worktrees.py --write-paths` records the checked local paths there without
changing commit identities. `--manifest` selects a separate local manifest for
reproduction. Machine-specific paths are local setup values, not shared snapshot
identities. The committed Windows paths remain the original handoff's locations.

`build_t2_benchmark.py` regenerates only the named T2 set. Its `--check` mode compares
all generated bytes without writing. `.gitattributes` pins generated T2 artifacts
to LF for cross-platform reproducibility.

## Provenance and validation

T2 annotations hash exact Git file/span bytes. Existing retrieved records use
normalized displayed `text` and `content_hash`; `validate_recorded_evidence()`
checks that representation against the recorded parent. It performs no trace
analysis, ranking-metric calculation or search control.

Tests cover benchmark input isolation, schema/source consistency, future-file
exclusion, source hashes, line spans, symbols and detached-worktree safety.
The results and execution environment are recorded in `t2_validation_results.md`.
Human relevance review, benchmark acceptance and experimental execution are not
represented as completed source checks.
